- 로그인 후 전역 내비 형태 (1·5번 표 기준, 앱 단위 10개)
  - 왼쪽 사이드바가 주 내비 6 — 리캐치, 뮤즈바이, 잔디, 채널톡(아이콘 레일 + 하위 패널), 사방넷(아이콘 레일), 리스닝마인드(아이콘 레일)
  - 상단 GNB + 왼쪽 사이드바 혼합 2 — 당근 비즈니스, 뿌리오(왼쪽은 메뉴가 아닌 정보 패널)
  - 상단 GNB만, 하위 메뉴는 설정·마이페이지에서만 왼쪽에 2 — Clarity, 위시켓
  - 가운데 떠 있는 둥근 pill 내비: 0
- 조직(학교) 전환 자리: 왼쪽 위(사이드바 머리) 3 — 잔디, 당근(사이드바 머리 + GNB 오른쪽 둘 다), 채널톡(상단 바 왼쪽 칩) / 로고 옆 드롭다운 1 — Clarity / 사이드바 아래 1 — 뮤즈바이 / 헤더 텍스트 1 — 사방넷("회사명 (서비스코드)")

## 관찰 요약

1. 데스크톱 업무 화면은 "화면 폭을 다 쓴다". 본문을 가운데 좁게 두는 경우는 설정·폼(채널톡 약 520px, 당근 관리자 홈 약 860px)뿐이고, 목록·대시보드는 사이드바 오른쪽 전체를 채운다(리캐치·사방넷·채널톡).
2. 내비는 왼쪽 사이드바가 다수다. 공통 구조는 "맨 위 조직(또는 로고) → 섹션 제목으로 묶은 메뉴 → 맨 아래 도움말·설정·내 계정"이다(리캐치·잔디·뮤즈바이). 상단 GNB형(Clarity·위시켓)도 설정 화면에서는 결국 왼쪽 하위 메뉴를 쓴다.
3. 목록 머리는 거의 같은 3줄이다: ① 제목 + 개수(왼쪽) / 검색 + 주 버튼(오른쪽) ② 저장된 보기·하위 탭 ③ 필터(왼쪽) / 내보내기·보기 전환(오른쪽). 표는 체크박스 열 + 정렬 가능한 열 제목, 행을 고르면 일괄 동작이 나타난다(리캐치는 바닥에 떠 있는 바, 뿌리오·사방넷은 표 위 고정 버튼).
4. 한 건 상세는 모달이 아니다. 목록을 보면서 보는 경우 오른쪽 드로어·패널(리캐치·채널톡), 무게 있는 대상이면 별도 페이지 + 되돌아가기(당근)로 나뉜다. 모달은 "짧은 입력·일괄 수정·필터·완료 안내"에만 쓰였다.
5. 대시보드는 "해야 할 일/상태 숫자"를 맨 위 한 줄에 두고(사방넷 단계별 숫자 띠, 당근 미션 카드), 그 아래 2~3열 격자에 목록형 위젯(공지·현황)과 그래프를 섞는다. 위젯마다 "전체보기 >"로 해당 목록 화면에 연결한다.
6. 로그인 전 화면은 두 가지다: 반 나눔(왼쪽 폼 + 오른쪽 브랜드 패널, 뮤즈바이)과 회색 배경 가운데 카드(잔디·유광기). 랜딩은 상단 GNB 오른쪽에 "로그인(테두리) + 시작/등록(채움)" 짝이 공통이다.

## Lab_Stock 데스크톱에 가져올 것 (구조·배치만 — 색·폰트는 기존 규칙 유지: 무채색 + 핑크=결정 신호, 하늘색=선택 강조)

- 전역 내비: 가운데 떠 있는 `nav-pill`을 데스크톱에서 없애고 왼쪽 사이드바(펼침 약 200~240px, 접으면 아이콘 레일)로 바꾼다. 맨 위에 학교명 블록(학교가 하나면 표시만, admin이 여럿 관리하면 ▾ 전환), 가운데 섹션 묶음 메뉴, 맨 아래 도움말·설정·내 계정(이름·역할). — 리캐치·잔디·당근 구조. N1(학교별 분리) 관점에서도 "지금 어느 학교 데이터인지"가 항상 왼쪽 위에 보인다.
- 목록(시약 목록 등): 카드 목록 대신 데이터 테이블로. 머리 3줄 구조(제목+개수 / 검색+주 버튼 오른쪽 위, 저장된 보기·탭, 필터 왼쪽 / 내보내기 오른쪽), 체크박스 열 + 정렬 가능한 열 제목, 행 hover 표시, 선택 시 바닥 가운데 일괄 동작 바(리캐치형). 개수가 많으면 표 아래 가운데 페이지 번호(뿌리오·사방넷), 기간 조건은 빠른 기간 세그먼트 + 날짜 범위(리디·사방넷).
- 목록-상세: 시약 한 건 보기·사용 기록 입력은 모달이 아니라 오른쪽 드로어(목록을 가리지 않음, 전체 화면 전환 버튼 포함). 드로어 안은 "제목 → 상태/메타 칩 → 탭 → 항목|값 2열" 순서(리캐치).
- 모달은 짧은 입력(항목 하나 추가)·일괄 수정·완료 안내·확인에만. 모바일 바텀시트 중 "선택지 고르기"류는 컨트롤 아래 드롭다운/팝오버로 옮긴다(리캐치 검색 범위, 잔디 팝오버).
- 홈(대시보드): 맨 위 한 줄에 "지금 처리할 것" 숫자 타일(사방넷 띠·당근 통계 타일), 아래 2~3열 격자에 최근 활동 표·공지·현황 위젯, 위젯마다 "전체보기 >" 연결. 기존 모바일 홈 바로가기 그리드는 데스크톱에서는 사이드바 + 목록 머리 주 버튼이 대신한다.
- 폼·설정: 설정은 왼쪽 하위 메뉴 + 본문(Clarity·위시켓). 본문 폼은 가운데 한 열 약 520~680px, "라벨 | 컨트롤" 가로 행 + 구분선(채널톡). 긴 생성 흐름은 스텝퍼 + 오른쪽 요약 열에 주 버튼(뮤즈바이).
- 로그인 전: 로그인·회원가입은 반 나눔(왼쪽 폼 / 오른쪽 서비스 소개 패널) 또는 회색 배경 가운데 카드 중 하나로 통일. 회원가입은 번호 붙은 섹션 + 구분선(유광기). 둘러보기(게스트) 화면은 로그인 후와 같은 사이드바 구조를 그대로 보여 주는 방식이 있다(리스닝마인드).

## 선택지

### A. 왼쪽 사이드바 + 테이블 + 오른쪽 상세 드로어 (리캐치·채널톡형)

- 구성: 사이드바(학교명 위 / 섹션 메뉴 / 계정 아래) · 본문 전체 폭 테이블 · 행을 누르면 오른쪽 드로어(약 400~520px)
- 장점: "컴퓨터 웹앱" 느낌이 가장 분명하다. 목록을 보면서 여러 시약을 빠르게 넘겨 볼 수 있어 교사·admin의 점검·정리 작업에 맞다. 모바일의 상세 시트 → 데스크톱 드로어로 구조 대응이 1:1이라 화면 수가 늘지 않는다.
- 단점: 1440 폭에서 사이드바 + 표 + 드로어가 동시에 열리면 표 열이 줄어든다(드로어 열 때 일부 열 숨김 규칙이 필요). 드로어 안에서 긴 폼(신규 등록)은 답답하다 → 등록은 별도 페이지나 큰 모달로 분리해야 한다.

### B. 상단 GNB + 테이블 + 상세 페이지 이동 (위시켓·당근 광고 상세·Clarity형)

- 구성: 전폭 상단 GNB(로고 · 큰 메뉴 4~5개 · 오른쪽 학교 선택/계정) · 목록 페이지는 테이블 · 행을 누르면 상세 페이지(맨 위 "← 목록" 되돌아가기)
- 장점: 지금의 `nav-pill`을 전폭 GNB로 펴는 것이라 변경 폭이 가장 작다. 메뉴 수가 적은 Lab_Stock(학생 역할은 특히)에 단순하다. 상세 페이지는 폭을 다 써서 사용 기록 표·사진 등을 넉넉히 보여 줄 수 있다.
- 단점: 목록 ↔ 상세를 오갈 때마다 화면이 바뀌어 여러 건 점검이 느리다. 섹션이 늘면 GNB가 붐빈다(뿌리오처럼). "모바일 넓힌 느낌"을 덜 지우는 쪽이다.

### C. 혼합 — 상단 바(학교 전환·계정) + 왼쪽 섹션 사이드바 + 테이블 + 드로어, 무거운 상세만 페이지 (당근 비즈니스형)

- 구성: 얇은 상단 바(로고 · 오른쪽 알림·학교 선택·계정) + 왼쪽 사이드바(섹션 묶음, 접고 펴기) + 목록은 테이블 + 한 건 보기는 드로어, 등록·설정·관리자 화면은 페이지
- 장점: 학교 전환·계정을 상단에 고정해 N1 맥락이 강하게 보이고, 사이드바는 메뉴만 담아 단순해진다. 가벼운 보기(드로어)와 무거운 작업(페이지)을 나눠 A의 "드로어 안 긴 폼" 문제를 피한다.
- 단점: 상단 바와 사이드바 둘 다 있어 세로·가로 공간을 모두 조금씩 쓴다(당근은 학교 선택이 두 군데로 중복됨 — 한 곳으로 정해야 함). 규칙(어떤 화면이 드로어, 어떤 화면이 페이지)을 design.md에 따로 적어야 해 하네스 규칙이 늘어난다.
