# PRD: (가칭 미정) 과학실 시약 관리 SaaS

## 1. 한 줄 설명
고등학교 과학실 시약장의 시약 종류·재고량·입고일자·사용날짜·사용자를 확인하고,
QR코드로 MSDS를 연결하며, 재고가 부족해지면 판매처를 연결하는 SaaS.

## 2. 사용자
- 전국의 과학 교사와 학생
- 학교마다 admin이 있고, 같은 학교의 다른 교사·학생이 함께 사용한다.

## 3. 역할과 권한
| 역할 | 할 수 있는 일 |
|---|---|
| 학생 | 사용량 기록 |
| 교사 | 입고(수량 올리기), 시약 정보 입력, 사용량 기록 |
| admin | 교사 권한 전체 + 사용자 초대·삭제, 판매처 설정 |

## 4. 핵심 행동
- 수량을 올린다(입고).
- 자료를 입력한다(시약 정보, 실험 매뉴얼).
- 사용량을 저장한다.

## 5. 재주문 기준
- 사용자가 실험 매뉴얼을 올리고 조 수를 입력하면, 1반 1회 실험에 필요한 양을 자동으로 계산한다.
- 현재 재고가 이 양보다 적으면 판매처를 연결한다.
- 계산 방식: AI(저렴한 Gemini 모델)로 매뉴얼에서 시약별 사용량을 추출 → 조 수를 곱함.
  - API 키는 서버에서만 사용한다.
  - 추출 결과는 사용자가 확인한 뒤 저장한다.
- 학교 목록은 나이스(NEIS) 교육정보 개방 포털 학교기본정보 API로 불러온다. NEIS 인증키도 서버에서만 사용한다.

## 6. 데이터 원칙
- 학교별로 데이터를 따로 관리한다. (다른 학교의 시약·재고·사용 기록과 섞이지 않는다.)

## 7. 화면 범위 (이번 시안)
1. 로그인(학교 선택: 시/도 → 지역(시/군/구) → 학교, 나이스(NEIS) 학교기본정보 API)
2. 시약 목록(재고 부족 표시)
3. 시약 상세(MSDS QR 연결 포함)
4. 사용 기록 입력
5. 실험 매뉴얼 업로드 → 추출 결과 확인
6. 재주문 알림 → 판매처 연결

## 8. 기기
- 모바일 버전과 데스크탑 버전을 함께 만든다.
- 사용자의 접속 환경(화면 크기)에 따라 화면 비율이 동적으로 바뀐다(반응형).

## 9. 미정
- 서비스 이름
- 출시 성공 기준
- 판매처 등록 주체 (기본 가정: admin)
