# 파이프라인 (R3)

> 목적·완료 기준: harness/r2-purpose.md
> 작업 흐름 원본: docs/story-work.md (문장 번호로 연결)

## 1. 단계

```
S1 레퍼런스 ─▶ S2 설계 ─▶ S3 키스크린 ─▶ [G-승인] ─▶ S4 전체 화면 ─▶ S5 검수
 (문장1·2)     (문장3)     (문장4)          (문장5)          (문장6)         (문장7)
```

- 단계 수 = 5 (사람 승인은 단계가 아니라 S3→S4 사이 게이트)

## 2. 단계별 입출력

| 단계 | 입력 | 출력 | 통과 조건 (셀 수 있는 형태) |
|---|---|---|---|
| S1 레퍼런스 | 화면 ID 목록, PRD §7 | 레퍼런스 모음 + 반영 항목 표 | 화면당 uibowl 레퍼런스 3~5개, 레퍼런스마다 "가져올 것" 1줄 + ui_url 1개 |
| S2 설계 | S1 출력, PRD, story-service | 화면 설계서 | 대상 화면마다 구성 요소 목록 ≥ 1, 역할별(학생·교사·admin) 노출 여부 표 1개 |
| S3 키스크린 | S2 출력, design.md | mobile 키스크린 + 노드 JSON | 키스크린 2~3장, 390×844 |
| S4 전체 화면 | 승인된 S3, S2, design.md | 대상 화면 × {mobile, desktop} 프레임 + 노드 JSON | 프레임 수 = 대상 화면 수 × 2 |
| S5 검수 | S4 노드 JSON, design.md, story-service | 위반 목록 | 행마다 규칙 ID · 노드 · 실제값 · 허용값 |

## 3. 키스크린 선정 규칙

- 기본 = 화면 2(시약 목록), 3(시약 상세), 6(재주문 알림)
- 대상 화면 목록에 위 화면이 없으면 → 대상 목록 앞에서부터 최대 3장

## 4. 되돌아가는 지점

| 발생 | 복귀 | 최대 횟수 | 초과 시 |
|---|---|---|---|
| S1 레퍼런스 < 3개 (화면 기준) | S1 (검색어 변경) | 2회 | 멈추고 사람에게 넘김 |
| G-S2 역할·N2 위반 (R5 추가) | S2 | 2회 | 멈추고 사람에게 넘김 |
| G-S3 사전 점검 위반 ≥ 1건 (R5 추가) | S3 (위반 노드만) | 3회 | 멈추고 사람에게 넘김 |
| G-승인 거절 | S3 (사유에 "설계" 포함 시 S2) | 제한 없음 | — |
| S5 위반 ≥ 1건 | S4 (위반 노드만 수정) | 3회 | 멈추고 사람에게 넘김 |

## 5. 멈칫 → 게이트 연결 (R5에서 구체화)

| story-work 멈칫 | 연결 위치 |
|---|---|
| 문장 2 반영할 부분 판단 | S1 통과 조건 |
| 문장 5 컨셉 협의 | G-승인 |
| 문장 7 가이드 위반 검수 | S5 |
