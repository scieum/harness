# 하네스 목적 (R2)

> 고정 입력: docs/PRD.md, docs/design.md, docs/story-service.md, docs/story-work.md
> 이 파일들은 하네스 실행 중에 수정하지 않는다.

## 1. 매번 달라지는 것

| 항목 | 셀 수 있는 형태 |
|---|---|
| 대상 화면 목록 | 화면 ID ⊂ {1..16} (PRD §7 번호, 7~14는 2026-10-02·15는 2026-10-03 추가), 개수 1~16 (16 MSDS 요약 2026-10-08 추가) |
| 그 외 | 없음. PRD·design.md 변경은 하네스 밖에서 한다 |

## 2. 사용자

| 역할 | 누구 | 하는 일 | 인원 |
|---|---|---|---|
| 실행자 | 나(디자이너) | 하네스 실행, 자연어 트리거 | 1 |
| 승인자 | 내부 관계자 | 컨셉 시안 승인 (story-work 문장 5) | 승인 기록 1건 |

## 3. 프레임 규격

| 이름 | 크기 | 용도 |
|---|---|---|
| mobile | 390×844 | 기준 프레임 |
| desktop | 1440×900 | 확정 (design.md "Provisional"을 대체) |
| 최소 폭 | 360px | 가로 스크롤 0 |

## 4. 산출 매체

- 최종: Figma MCP로 생성한 Figma 프레임
- 판정용: 프레임별 노드 데이터 JSON (fill 색, cornerRadius, fontFamily, fontWeight, fontSize, effects 등)
  → 판정 스크립트는 Figma가 아니라 이 JSON을 센다

## 5. 완료 기준 (한 문장)

PRD §7 화면 15개 × 프레임 2종 = **30개 프레임**이 Figma에 있고,
검수 스크립트 위반 **0건**, 승인 기록 **1건**이 있으면 완료다.

- 키스크린 2~3장(mobile)은 중간 산출물이며 완료 기준에 포함하지 않는다.
- 부분 실행(화면 ID 일부)의 완료 = 지정한 화면 수 × 2 프레임, 위반 0건.
